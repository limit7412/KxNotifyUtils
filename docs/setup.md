# セットアップガイド

KxNotifyUtils を導入して、VR 中に Windows の通知を HMD 内で受け取れるようにするまでの手順をまとめる。

## 1. 実行ファイルを置く

[Releases](https://github.com/limit7412/KxNotifyUtils/releases) から `KxNotifyUtils.exe` を取得し、好きな場所に置く。
インストーラは無く、zip の展開も要らない。

置き場所は任意でよいが、SteamVR への登録は exe の絶対パスに依存する。
そのため、置いたあとに移動する場合は次の起動で登録し直すことになる（後述）。

## 2. 通知へのアクセスを許可する

Windows の設定 > プライバシーとセキュリティ > 通知 を開き、KxNotifyUtils に通知へのアクセスを許可する。

初回起動時にアプリから許可を要求するが、パッケージ化されていない Win32 アプリでは要求が拒否され続ける既知の問題がある。
その場合はトレイ通知から設定画面へ誘導するので、手動で許可する。
許可が下りるまで中継は始まらないが、アプリはそのまま常駐を続け、許可された時点で中継を開始する。

## 3. XSOverlay を起動して疎通を確かめる

XSOverlay を起動した状態で、トレイアイコンを右クリックして「テスト通知を送信」を選ぶ。
HMD 内に通知が出れば設定は完了である。

出ない場合は次を確認する。

- XSOverlay が build 667 以降であること（WebSocket API はこのビルドから公開されている）
- XSOverlay 側で通知の受け取りが無効になっていないこと
- 設定ウィンドウの通知先タブで、WebSocket ポートが XSOverlay の設定と一致していること（既定は 42070）

WebSocket でうまくいかない場合の退避手段として、送信経路を UDP に切り替えられる。
ただし UDP はレガシー API であり、恒久的な運用先としては勧めない。

## 4. SteamVR の自動起動を設定する

初回起動時に、SteamVR のアプリケーションとして自分自身を登録し、自動起動を有効にする。
以降は SteamVR を起動すると KxNotifyUtils も起動し、SteamVR を終了すると一緒に終了する。

登録と解除はトレイメニューか、設定ウィンドウの SteamVR タブから切り替えられる。

SteamVR より先に KxNotifyUtils を手動で起動した場合、その時点では OpenVR の初期化に失敗する。
このときは 60 秒ごとに初期化をやり直すため、後から SteamVR を起動しても終了の連動は働く。

## 5. アプリごとの見え方を整える

トレイメニューの「設定」で設定ウィンドウを開く。

まず「既定の通知設定」タブで、すべての通知に共通する見え方を決める。
表示時間は固定（`fixed`）と、文字数から計算する可変（`dynamic`）のどちらかを選べる。

次に「アプリ別ルール」タブで、アプリごとの違いを足す。
ルールは上から順に評価され、`match_app_id` が前方一致した最初のものが採用される。
チェックを外した項目は既定の通知設定を引き継ぐため、変えたい項目だけをチェックすればよい。

`match_app_id` に何を書けばよいかわからない場合は、同じタブの「観測した app_id」から選ぶ。
起動してから届いた通知の `app_id` が並ぶので、そこから選んで条件にできる。

同じタブのフィルタで、中継するアプリを絞り込める。
`blacklist` は挙げたアプリを落とし、`whitelist` は挙げたアプリだけを通す。

## 二重に起動したとき

KxNotifyUtils は 1 台につき 1 プロセスだけ動く。
手動で起動した後に SteamVR の自動起動が走った場合など、二度目のプロセスは既存のものを見つけて何もせず終了する。
2 つのプロセスが同じ通知を別々に取得すると、通知が重複して届くためである。

## 通知が届かないとき

**通知センターに入らない通知は取得できない。**
応答不可モード（フォーカスアシスト）が有効な間や、アプリ側でバナーを切っている場合、通知が通知センターに入らないことがある。
VR ゲームがフルスクリーン最適化で通知を抑制する場合も同じである。
確実に中継したいアプリは、応答不可モードの優先リストに入れておく。

**XSOverlay が動いていない間の通知は捨てられる。**
接続していない間に発生した通知はキューに溜めず破棄する。
XSOverlay が動いていない状況は VR の外にいる可能性が高く、そのとき通知は通常のトーストで見えているためである。

**ログを見る。**
トレイメニューの「ログフォルダを開く」で `%APPDATA%\KxNotifyUtils\logs\` を開ける。
設定ウィンドウの全般タブでログレベルを `debug` にすると、中継した通知の `app_id` と件名が残る。
本文は個人情報を含みやすいため、`debug` でも記録しない。

## 実行ファイルを移動したとき

exe を移動すると、次回の起動時に vrmanifest を作り直して SteamVR へ登録し直す。
利用者が何かする必要はない。

ただし SteamVR の起動中に移動した場合、SteamVR 側が新しいパスを認識するのは再登録の後になる。
そのため自動起動が一度だけ失敗することがある。
気になる場合は SteamVR を再起動する。
