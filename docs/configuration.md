# 設定リファレンス

設定ファイルは `%APPDATA%\KxNotifyUtils\config.json` に置く。
設定ウィンドウと同じファイルを読み書きするため、どちらで編集してもよい。
外部のエディタで書き換えたあとは、トレイメニューの「設定を再読み込み」で取り込む。

不正な JSON を読んだ場合は直前の有効な設定で動作を続け、トレイ通知でエラーを知らせる。

## 全体の構成

```json
{
  "sources": {
    "windows": {
      "enabled": true,
      "polling_interval_ms": 500
    }
  },

  "sinks": {
    "xsoverlay": {
      "enabled": true,
      "transport": "websocket",
      "websocket_port": 42070,
      "udp_port": 42069
    }
  },

  "filter": {
    "mode": "blacklist",
    "apps": ["Microsoft.Windows.Explorer"]
  },

  "defaults": {
    "timeout_mode": "dynamic",
    "timeout": 6.0,
    "dynamic_timeout": { "base": 2.0, "reading_speed": 12, "min": 3.0, "max": 15.0 },
    "max_body_length": 200,
    "title_template": "{app_name}: {title}",
    "icon": "app",
    "opacity": 1.0,
    "volume": 0.5,
    "sound": "default"
  },

  "rules": [
    {
      "match_app_id": "com.squirrel.Discord",
      "volume": 0.8,
      "sound": "C:/sounds/discord.wav"
    }
  ],

  "steamvr": {
    "auto_launch_registered": true,
    "last_exe_path": "D:/tools/KxNotifyUtils.exe",
    "auto_launch_configured": true
  },

  "update": {
    "check_enabled": true,
    "channel": "stable",
    "notified_version": ""
  },

  "log_level": "info",
  "language": "auto"
}
```

`sources` と `sinks` は識別子をキーにしたオブジェクトである。
将来ソースやシンクが増えたときは新しいキーが足されるだけで、既存のキーはそのまま読める。

## sources.windows

Windows のデスクトップ通知を監視する。

- **enabled**：このソースを使うかどうか。
- **polling_interval_ms**：通知一覧を確認する間隔。100 から 5000 の範囲で指定する。既定は 500 である。

間隔を短くすると通知が出るまでの遅れは減るが、そのぶん CPU を使う。
500 ミリ秒で体感の遅れはほとんど無い。

## sinks.xsoverlay

XSOverlay へ通知を送る。

- **enabled**：このシンクを使うかどうか。
- **transport**：`websocket` または `udp`。既定は `websocket` である。
- **websocket_port**：XSOverlay の WebSocket API のポート。既定は 42070 である。
- **udp_port**：レガシーの UDP API のポート。既定は 42069 である。

`udp` は WebSocket に問題が出た場合の退避手段として残しており、恒久的な運用先としては勧めない。

有効な通知先が 1 つも無い設定は保存できない。
中継先が無いまま常駐するのは、設定を書き間違えている可能性が高いためである。

## filter

どのアプリの通知を中継するかを決める。

- **mode**：`blacklist`（挙げたアプリを落とす）または `whitelist`（挙げたアプリだけを通す）。
- **apps**：`app_id` の前方一致で比較する文字列の配列。

`app_id` は Windows がアプリに与える識別子（AppUserModelId）である。
何を書けばよいかは、設定ウィンドウのアプリ別ルールタブにある「観測した app_id」から選べる。

## defaults と rules

`defaults` はすべての通知に共通する見え方で、`rules` はアプリごとの違いである。
`rules` の各項目には `defaults` との差分だけを書けばよく、書かなかった項目は `defaults` を引き継ぐ。

`rules` は上から順に評価され、`match_app_id` が前方一致した最初のものが採用される。
順序に意味があるため、細かい条件を先に、広い条件を後に置く。

指定できる項目は次のとおりである。

- **timeout_mode**：`fixed` なら `timeout` の秒数をそのまま使い、`dynamic` なら文字数から計算する。
- **timeout**：`fixed` のときの表示時間（秒）。
- **dynamic_timeout**：`dynamic` のときの係数。`base + 文字数 / reading_speed` を `min` と `max` でクランプした値を表示時間にする。文字数は件名と本文の合計である。`min` と `max` はどちらも 0 より大きい値で指定する。`rules` では係数ごとに書け、書かなかった係数は `defaults` を引き継ぐ（例：`"dynamic_timeout": { "base": 5.0 }`）。
- **max_body_length**：本文の最大文字数。0 から 5000 の範囲で指定する。超えた分は切り詰め、末尾に省略の記号を付ける。0 を指定すると本文を載せない。無制限を表す値は無い。
- **title_template**：件名の組み立て方。`{app_name}`、`{app_id}`、`{title}`、`{body}` を展開する。
- **icon**：`app`（アプリのアイコンを使い、取れなければ `default` に落とす）、`default`、`warning`、`error`、または PNG ファイルのパス。パスを指定した場合は保存時に中身を確かめ、PNG でなければ保存できない。保存後にファイルが差し替わって PNG でなくなった場合は `default` に落とす。
- **opacity**：透明度。0.0 から 1.0 で指定する。
- **volume**：通知音の音量。0.0 から 1.0 で指定する。
- **sound**：`default`、`warning`、`error`、音声ファイルのパス、または空文字列（ミュート）。

`rules` のマッチ条件は現在 `match_app_id` だけである。
ソースが増えたときにソース別のルールを書けるよう、`match_` で始まる名前を条件のために予約している。

## steamvr

- **auto_launch_registered**：SteamVR の自動起動に登録しているか。
- **last_exe_path**：前回登録したときの実行ファイルのパス。移動の検知に使う。
- **auto_launch_configured**：自動起動の登録について一度でも決着がついたか。初回の自動登録を行うかどうかの判断に使う。登録したときと、利用者が解除したときに立つ。

どれもアプリが書き込む記録であり、手で編集する項目ではない。

## update

更新の確認の設定である（[#10](https://github.com/limit7412/KxNotifyUtils/issues/10)）。

- **check_enabled**：起動時と 24 時間ごとに GitHub Releases を見に行くか。既定は `true` である。
- **channel**：`stable` か `test` を指定する。既定は `stable` である。
- **notified_version**：バルーンで知らせ済みの版のタグ。アプリが書き込む記録であり、手で編集する項目ではない。

配布物は exe 1 ファイルであり、インストーラを持たない。
インストーラ経由の更新通知が無いため、確認しないとリリースページを見に行くまで新しい版に気付けない。

`stable` は安定版（`X.Y.Z`）だけを見る。
`test` は master への取り込みで自動生成されるプレリリース（`X.Y.Z-testN`）も見る。
同じ `X.Y.Z` なら安定版のほうが新しいものとして扱う。

新しい版を見つけたら、トレイのバルーンで一度だけ知らせる。
知らせた版は `notified_version` に残すため、再起動しても同じ版を知らせ直さない。
本体は SteamVR の自動起動で立ち上がるので、覚えておかないと VR を始めるたびに同じバルーンが出る。
設定編集ウィンドウの情報タブには、見つけた版とリリースページを開くボタンが出る。
すぐ確かめたいときは、トレイメニューの「更新を確認」を使う。

リリースが多く一覧を取りきれなかった場合、「最新である」とは言わない。
取りきれなかった範囲に、より新しい版が残っている可能性があるためである。
このときトレイメニューから押すと「更新を確かめきれなかった」と出る。

確認に失敗した場合、自動の確認では警告ログに残すだけで知らせない。
回線の無い環境で起動するたびに知らされても対処のしようがないためである。
トレイメニューから押したときだけ、確認できなかったことを知らせる。

`check_enabled` を `false` にしても、トレイメニューからの手動の確認は使える。
手動で見つけた版は、確認が無効でも情報タブに出る。

`check_enabled` が `true` のとき、`channel` を変えるとその場で確かめ直す。
直前の結果は別のチャンネルのものであり、次の確認まで表示に残すわけにはいかないためである。

`false` のときは確かめ直さない。
自動の確認を切っているのは「こちらから見に行かない」という指定であり、
チャンネルの選択を変えたことはそれ自体では確認の要求ではない。
新しいチャンネルで確かめたくなったら、トレイメニューの「更新を確認」を使う。
このとき情報タブは、別のチャンネルの結果を出さずに「更新の確認は無効である」と表示する。

なお手元でビルドした版（`0.1.0-dev`）では確認を行わない。
運用しているタグの綴りから外れており、リリースの版と比べても順序が決まらないためである。

ダウンロードと置き換えはこの設定に含まない。第 2 段階として別途行う（[#10](https://github.com/limit7412/KxNotifyUtils/issues/10)）。

## log_level

`trace`、`debug`、`info`、`notice`、`warn`、`error`、`fatal`、`none` のいずれかを指定する。
既定は `info` である。

`info` では起動と終了、シンクの接続と切断、登録の操作、1 分ごとの中継件数を記録する。
`debug` を足すと、中継した通知の `app_id` と件名も記録する。
本文は個人情報を含みやすいため、`debug` でも記録しない。

## language

`auto`、`ja`、`en` のいずれかを指定する。
既定は `auto` で、Windows の表示言語が日本語なら `ja`、それ以外なら `en` を使う。

変更が反映されるのは次回の起動時である。
画面は起動時に一度だけ組み立てるため、動作中の切り替えには追従しない。

この設定が変えるのは、トレイのメニューとバルーン、設定編集ウィンドウの表示である。
次のものは対象ではない。

- **中継する通知の中身**：title と body は監視対象のアプリが作った文字列であり、そのまま運ぶ。
- **ログ**：開発者向けの記録であり、日本語のままとする。
- **設定の検証エラー**：「保存できない」などのダイアログに出る個々の理由は日本語のままである。同じ文字列がログにも書かれており、翻訳するとログが混在言語になる。切り離しは別途行う（[#4](https://github.com/limit7412/KxNotifyUtils/issues/4)）。

## 設定ファイルを読めなかったとき

JSON が壊れているか検証に通らない場合、アプリは初期設定で起動し、トレイでその旨を知らせる。
このとき設定ファイルは書き換えず、そのまま残す。

読めなかった内容を初期設定で上書きすると、利用者が直す前にルールごと失われるためである。
自動起動の登録のようにアプリが記録を書き戻す操作も、この間は書き出さず、動作への反映だけを行う。

## アプリが書き戻す記録と手編集

`steamvr` セクションと `update.notified_version` は、利用者の操作を伴わずにアプリが書き込む。
SteamVR の同期は起動時と再試行のたびに、更新の確認は起動時と 24 時間ごとに走る。

編集中にこれらが走っても、手で書いた内容は失われない。
書き戻す直前に設定ファイルの更新時刻を見て、読み込んだときから変わっていれば読み直し、記録だけを載せ替えて書き出す。

ただし読み直した内容を動作へ反映はしない。
編集の途中のものへ勝手に切り替わらないようにするためである。
書いた内容を動かすには、これまでどおりトレイメニューの「設定を再読み込み」を選ぶ。

読み直した設定が壊れているか検証に通らない場合は、書き戻し自体を見送る。
直している途中のファイルへ記録だけを載せて、不正なまま固定してしまわないためである。
このとき記録は次に書き戻す機会まで残らないが、SteamVR の同期も更新の確認も繰り返し走るため、設定を直せば次の機会に書き戻される。

直し方は 2 通りある。

- 設定ファイルを手で直し、トレイメニューの「設定を再読み込み」を選ぶ。
- 設定編集ウィンドウで各項目を確かめ、「保存」を押す。この保存は読めなかったファイルを置き換える。
